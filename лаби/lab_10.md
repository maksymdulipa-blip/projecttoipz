## 3. Командний workflow

git clone https://github.com/maksymdulipa-blip/projecttoipz

git switch -c feature/gameplay

Після підготовки змін: git add .; git commit -m "Update gameplay"; git push -u origin feature/gameplay.

На GitHub створити Pull Request до main. Інший учасник перевіряє зміни, залишає коментарі. Автор виправляє зауваження у своїй гілці та повторно надсилає commit. Після погодження виконати Merge pull request.

## 4. Приклад конфлікту

Якщо два учасники змінять однаковий рядок LogicScript.cs, Git може створити конфлікт. Виконати git fetch origin та git merge origin/main у робочій гілці, вручну узгодити рядки між маркерами \<\<\<\<\<\<\<, =======, \>\>\>\>\>\>\>, після чого git add Assets/LogicScript.cs, git commit і git push. Це навчальний сценарій, а не зафіксований конфлікт.

## Висновок

Описано командний процес, гілки та спосіб вирішення конфлікту. Створення гілок, PR і їх злиття потребує дій учасників у GitHub; вони не підтверджені.
