# Практична робота №3. Життєвий цикл програмного забезпечення

## 1. Вибір моделі життєвого циклу
Для розробки даної казуальної гри було обрано **ітеративно-інкрементну модель (Agile/Scrum)**. Вона дозволяє розбивати процес на короткі спринти та поступово нарощувати функціонал:
1. Базове керування персонажем $\rightarrow$ 2. Генерація перешкод $\rightarrow$ 3. Механіка програшу та UI $\rightarrow$ 4. Монети та рівні.

## 2. Етапи життєвого циклу проєкту
1. **Аналіз та планування:** Опис ідеї, формулювання вимог і сценаріїв використання.
2. **Проєктування:** Створення архітектури класів (`BirdScript`, `LogicScript`, `PipeSpawn`, `PipeMoves`), діаграм та UI-макетів.
3. **Реалізація:** Написання скриптів на C# у редакторі Unity, верстка сцен (`MainMenu`, `GameScene`).
4. **Тестування:** Перевірка фізики зіткнень, коректності роботи тригерів `DeathZone` та відсутність багів при рестарті.
5. **Підтримка та розгортання:** Збірка проєкту під цільові платформи та версіонування у Git/GitHub.

## 3. Обґрунтування вибору
Гнучка модель дозволяє швидко реагувати на зміни в балансі гри, виправляти помилки фізики та додавати нові ігрові механіки без повного перепланування всього проєкту.
